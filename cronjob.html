给雷达装一个外部定时器

cron-job.org 每 5 分钟替你叫一次工。GitHub 自己的定时任务会迟到几小时，这是目前唯一能真正兜住的办法。

这页已经用不上了（2026-11-28 记录）

实测发现 GitHub 自带的 GITHUB_TOKEN 配上 actions: write 权限， 其实可以派发自己——每次运行开局就把下一次叫进队列，链路自己续得上。 所以既不需要注册 cron-job.org，也不需要生成任何令牌。下面内容仅留作备份参考。

这页的所有输入都只留在你手机上（浏览器本地），不会上传到任何地方。 填完点下面的「试一次」就知道通没通。

1建一个只够用的令牌

打开 New fine-grained token，按下面填：

Token namenews-radar-cron
Expiration1 year（到期前 GitHub 会提醒你）
Repository accessOnly select repositories → 只勾 fcshen/news-radar

权限（Page 下半部分）　GitHub 新版改了交互，权限要先「添加」再设级别，不是打勾：

  1. 找到 Permissions 区块，确认停在 Repositories 这个标签（不是 Account）
  2. 中间显示 No repository permissions added yet 是正常的，说明还没添加
  3. 点右上角 + Add permissions
  4. 在弹出的搜索框里输入 Actions
  5. 勾上 Actions，把它的访问级别设为 Read and write，然后点 Add permissions 确认

只要 Actions 这一项。不要加 Contents，不要加 Administration——用不上，泄露了危害也小。

加完会看到两行，别以为是加多了：Actions · Read and write 是你加的， Metadata · Read-only（标 Required） 是 GitHub 自动附带、且删不掉的必选项—— 它用来识别令牌能作用于哪些仓库。上面的计数显示 2 就是这个原因。

实在找不到？用老式令牌，两个勾就够

打开 Tokens (classic) → Note 填 news-radar-cron，Expiration 选 1 year，只勾这两个： repo 和 workflow。生成的令牌以 ghp_ 开头，用法完全一样。 唯一缺点是这个令牌对你名下所有仓库都有效，而 fine-grained 那个只对本项目有效。

生成后形如 github_pat_11ABC...（或 ghp_...），只显示一次，先粘到下面再关页面。

2粘进令牌，复制四条配置

令牌
URL
https://api.github.com/repos/fcshen/news-radar/actions/workflows/radar.yml/dispatches
方法
POST
请求头
Authorization: Bearer <你的令牌> Accept: application/vnd.github+json Content-Type: application/json X-GitHub-Api-Version: 2022-11-28
请求体
{"ref":"main","inputs":{"minutes":"4"}}

粘了令牌后，「请求头」里的占位符会自动替换成真实令牌，直接复制即可。

3先去 cron-job.org 建作业

别用主站的 /signup 地址：cron-job.org 已把控制台迁到子域名，主站上那些路径全是 404。 只能从 console.cron-job.org 进。
  1. 打开 console.cron-job.org/signup 注册（邮箱 + 密码，需点验证邮件；不要信用卡）
  2. 登录后（登录页）点 Create cronjob，新版也可能写作右上角 + New cronjob
  3. Title：金融雷达叫工
  4. URL：粘上面那条
  5. Schedule：选 Every 5 minutes（或自定义 */5 * * * *）
  6. 展开 Advanced → Request method 选 POST
  7. 同页 Headers 逐条添加上面那四行（名 / 值分开填）
  8. Request body 粘上面那段 JSON
  9. 勾上 Notify me when the job fails，保存
注意两点：① 连续失败 25 次它会自动停用作业（这是保护，不是 bug）；② 单次请求超过 30 秒会超时——但我们这条只是叫工，GitHub 几百毫秒就回 204，不会超时。

4现场验一次，别靠猜

点了会真的拉起一次采集，属于正常操作，不会重复推送已经推过的消息。

返回 204 就是成功（GitHub 成功时不返回内容）。若浏览器拦住跨域，改用电脑终端执行：
curl -X POST -H "Authorization: Bearer 令牌" -H "Accept: application/vnd.github+json" -d '{"ref":"main","inputs":{"minutes":"4"}}' 上面那条URL

回去看结果

Actions 页面里应出现一条触发方式为 workflow_dispatch 的运行，每 5 分钟一条。
